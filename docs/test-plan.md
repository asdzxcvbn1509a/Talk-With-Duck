## ระดับที่ 1–2: Unit Test และ Integration Test (อัตโนมัติ)

```bash
npm test            # รันทั้งสองฝั่งจาก root
```

| ชุดทดสอบ | ไฟล์ | ครอบคลุม |
|---|---|---|
| Server unit | `server/tests/unit/*.test.js` | ตรวจโดเมนอีเมล (จำกัดโดเมน/รับทุกโดเมน), JWT (หมดอายุ/ปลอม/alg none), เงื่อนไขเปิดปุ่มบัญชีทดสอบ (`DEV_LOGIN`), การซ่อนตัวตน, แยกลิงก์ YouTube, ตรวจข้อมูลด้วย zod |
| Server integration | `server/tests/integration/*.test.js` | ยิง REST API จริงกับฐานข้อมูล `talkwithduck_test` (สร้างอัตโนมัติจาก `DATABASE_URL`) · การเข้าสู่ระบบด้วย Google จำลองผลการตรวจ ID token (ไม่ต่อ Google จริง) · รายการห้องคาราโอเกะบอกเพลงที่กำลังเล่น (`nowPlaying`: คิวว่าง → ชื่อเพลง → คิวว่าง) |
| Server realtime | `server/tests/integration/realtime.test.js` | Socket.IO จริง: ส่งต่อ SDP/ICE, กันส่ง signal ข้ามห้อง, แจ้งสมาชิกใหม่ในห้อง (`room:member-joined`), แชท, ปิดไมค์, ออกจากห้อง, ซิงก์คาราโอเกะเฉพาะ host (ส่งมาว่าหยุดก็ยังเล่นต่อ), lobby, เปิดซ้ำหลายแท็บ |
| Client | `client/src/**/*.test.{js,jsx}` | สูตรซิงก์เพลง, ความดังเสียง (Speaking Indicator: ปัดค่าก่อนส่งให้หน้าเว็บ · render ใหม่เฉพาะช่องของคนที่พูด ไม่ใช่รายชื่อทั้งห้อง), roomStore ล่วงหน้าตอนเปิดหน้าห้องแล้วไม่ขอซ้ำ), เวลาในแชทและวันที่ในกระทู้แสดงเหมือนเดิมหลังใช้ตัวจัดรูปแบบร่วมกัน, คอมโพเนนต์ QuestionCard/RoomCard/YearFilter, ฟังก์ชันใน `src/api` ยิง method/path ถูกต้องทั้ง 35 ตัว, `useApiQuery`, หน้าเข้าสู่ระบบด้วย Google (บัญชีใหม่ต้องตั้งโปรไฟล์ก่อน, token หมดอายุ) และปุ่มบัญชีทดสอบ (มีในหน้าเข้าสู่ระบบตอน dev), ถามยืนยันก่อนออกจากห้อง (ปุ่มออก/เปลี่ยนหน้า/ปุ่ม back), การต่ออายุ session (ไม่มี cookie ได้ 204), socket ตอน dev ต่อผ่าน Vite proxy, ตัวเล่นคาราโอเกะ (ทุกคนรวมถึง host คลิกวิดีโอไม่ได้และไม่มีปุ่มควบคุม · เพลงโดนหยุดจากทางอื่นแล้วเล่นต่อเองตามเวลาของห้อง และ host ไม่บอกห้องให้หยุดตาม · host ส่งเวลาของห้องแม้ตัวเล่นของตัวเองช้า · ได้เป็น host กลางเพลงแล้วเล่นต่อโดยไม่โหลดใหม่ · host เปิดเพลงใหม่แล้วเบราว์เซอร์ไม่ยอมเล่นเองจะขึ้นปุ่มแตะเพื่อฟัง · เพลงถัดไปเป็นวิดีโอเดิมก็เริ่มใหม่ · หยุดเพลงเก่าเมื่อข้าม/ลบ · ห้องเล่นเลยท้ายเพลงแล้วไม่เริ่มเพลงเดิมใหม่ · ขึ้นเพลงถัดไปไม่สำเร็จแล้วกดข้ามซ้ำได้), หน้าต่างยืนยัน SweetAlert2 (ชื่อเล่นที่มี HTML แสดงเป็นข้อความ), ปรับหรือปิดเสียงเพื่อนรายคน (ค่าใน uiStore ถูกส่งให้ `<audio>` ของคนนั้น), หน้าผู้ดูแล (ปลดระงับบัญชีต้องกดยืนยันก่อน · ระงับจากการ์ดรายงานแล้วขึ้นในรายการบัญชีที่ถูกระงับทันที), หน้าต่าง (Modal) ไม่ดึงโฟกัสไปปุ่มปิดระหว่างพิมพ์รายงานหรือปรับเสียง และ Escape ปิดได้, ตัวนับข้อความที่ยังไม่อ่าน (เกิน 200 ข้อความ · ผู้ดูแลซ่อนข้อความ · ต่อใหม่หลังเน็ตหลุด), โหมดสว่าง/มืด (`theme.test.js`: เลือกเองแล้วจำค่าไว้ · "ตามเครื่อง" เปลี่ยนตามระบบ · ค่าที่จำไว้ไม่ถูกต้องใช้ตามเครื่อง), ลองโหลดใหม่หลังโหลดไม่สำเร็จ (`useApiQuery` retry กลับไปสถานะกำลังโหลด), การ์ดห้องคาราโอเกะบอกเพลงที่กำลังเล่น/คิวว่าง และวงกลม +N เมื่อสมาชิกเกิน 5 คน, ปุ่มส่งใจอัปเดตทันที (optimistic) และคืนค่าเดิมเมื่อ server ตอบไม่สำเร็จ, หน้าต่าง (Modal) กด Tab แล้วโฟกัสวนอยู่ในหน้าต่าง และล็อกการเลื่อนหน้าด้านหลัง, ปุ่มเลือกแบบแถบ (Segmented) ใช้ aria-pressed, แถบแจ้งเน็ตหลุดในห้อง (`connected` ใน roomStore เป็น false ตอน socket หลุด และกลับเป็น true เมื่อต่อได้) |

integration test จะล้างข้อมูลในฐาน `talkwithduck_test` ทุกครั้ง (ไม่แตะฐาน dev) และจะไม่รันถ้าฐานทดสอบชี้ไปที่ฐานเดียวกับ `DATABASE_URL`
