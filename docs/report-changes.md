# สิ่งที่ระบบจริงต่างจากรูปเล่ม (ใช้แก้บทที่ 3–5)

ระหว่างพัฒนามีการปรับรายละเอียดบางส่วนจากเอกสารโครงการ รายการด้านล่างบอกว่าต้องแก้หัวข้อไหนและแก้เป็นอะไร

## ตารางที่ 3.1 เทคโนโลยีที่ใช้

| แถว | เดิม | แก้เป็น |
|---|---|---|
| ระบบฐานข้อมูล | Supabase (PostgreSQL, Realtime, Storage) | PostgreSQL (ใช้งานจริงบน Supabase, ช่วงพัฒนาใช้ PostgreSQL + pgAdmin ในเครื่อง) เชื่อมต่อผ่าน **Prisma ORM** |
| การสื่อสารแบบเรียลไทม์ | Supabase Realtime (แชท/สถานะห้อง) | **Socket.IO** บน Express ใช้ทั้ง Signaling ของ WebRTC, แชท, รายชื่อผู้ร่วมห้อง, คิวเพลง และการซิงก์เพลงคาราโอเกะ |
| (เพิ่ม) การออกแบบหน้าจอ | – | Tailwind CSS, ไอคอน Lucide (lucide-react) และหน้าต่างยืนยัน SweetAlert2 |
| (เพิ่ม) การยืนยันตัวตน | – | เข้าสู่ระบบด้วยบัญชี Google (Google Identity Services) แล้วออก JWT ของระบบเอง · จำกัดโดเมนอีเมลได้ด้วย `ALLOWED_EMAIL_DOMAINS` |

**เหตุผลที่เปลี่ยนจาก Supabase Realtime:** token ออกโดย Express (JWT ของเราเอง) ซึ่ง Supabase ไม่รู้จัก การส่งข้อมูลเรียลไทม์ทั้งหมดผ่าน Socket.IO ช่องเดียวจึงง่ายและปลอดภัยกว่า เพราะ client ไม่ต้องเข้าถึงฐานข้อมูลโดยตรงเลย

## 3.5.1 การเตรียมสภาพแวดล้อม

- **ข้อ 4 (ไลบรารีฝั่งหลังบ้าน):** express, jsonwebtoken, google-auth-library, cors, helmet, cookie-parser, express-rate-limit, zod, socket.io, @prisma/client, @prisma/adapter-pg
- **ข้อ 7 (ค่าใน `.env`):** `DATABASE_URL`, `JWT_ACCESS_SECRET`, `GOOGLE_CLIENT_ID`, `YOUTUBE_API_KEY`, ค่า TURN

## 3.5.2 ตารางที่ 3.2 โครงสร้างฐานข้อมูล

**ตารางที่เพิ่ม:**
- `refresh_tokens`: เก็บ Refresh Token แบบ hash พร้อม rotated_at (ถูกแลกแล้ว) และ revoked_at (ถูกเพิกถอน) เพื่อหมุนและเพิกถอนได้
- `question_loves`: กันกดใจซ้ำ

**คอลัมน์ที่เพิ่ม:**
- `users`: google_sub (รหัสบัญชี Google ไม่ซ้ำกัน), email_verified_at, role, accepted_guidelines_at, is_banned · ไม่มีคอลัมน์รหัสผ่าน
- `rooms`: capacity, created_at, closed_at
- `room_members`: left_at (ออกจากห้องแบบ soft เพื่อเก็บสถิติ)
- `messages`: type (ข้อความ/สติกเกอร์), is_hidden
- `questions`: topic, is_hidden, created_at, updated_at
- `answers`: is_hidden, updated_at
- `song_queue`: thumbnail, status
- `reports`: details, reviewed_by, reviewed_at

**ความปลอดภัยระดับฐานข้อมูล:** เปิด Row Level Security ทุกตารางและเพิ่ม CHECK constraint (ชั้นปี 1–4 ฯลฯ)

## ตารางที่ 3.3 API และตารางที่ 3.4 เส้นทางหน้าเว็บ

- **API:** มี endpoint เพิ่มเข้ามา ดูรายการเต็มใน [api.md](api.md) (ตัวที่ติด ★)
  - ระบบสมาชิกเหลือ `/auth/google`, `/auth/refresh`, `/auth/logout` ถ้ารูปเล่มมี `/auth/register` หรือ `/auth/login` ให้แทนด้วย `/auth/google`
- **หน้าเว็บ:** เพิ่ม `/karaoke/:id`, `/qa/new`, `/me`, `/admin/reports`
  - ไม่มีหน้าสมัครสมาชิกแยก: `/login` เป็นหน้าเข้าสู่ระบบด้วย Google และเข้าครั้งแรกจะให้ตั้งชื่อเล่น ชั้นปี และน้องเป็ดในหน้าเดียวกัน

## 3.5.4 ระบบสมาชิก

- **เข้าสู่ระบบด้วยบัญชี Google:** ให้ Google ยืนยันตัวตนแทนการสมัครด้วยรหัสผ่านและยืนยัน OTP ทางอีเมล ใช้ได้ทั้งบัญชี Gmail และบัญชี `@mail.kmutt.ac.th` (Google Workspace for Education) ถ้าจะให้เฉพาะนักศึกษา ตั้ง `ALLOWED_EMAIL_DOMAINS=mail.kmutt.ac.th`
  - หน้าเว็บได้ ID token จากปุ่ม "Sign in with Google" แล้วส่งให้ server
  - server ตรวจลายเซ็นกับกุญแจของ Google, ตรวจว่า token ออกให้แอปนี้ (audience) และตรวจว่า Google เป็นเจ้าของอีเมลนั้นจริง (เป็น `@gmail.com` หรือ `hd` ตรงกับโดเมนของอีเมล)
- **ไม่เก็บรหัสผ่าน และไม่เก็บชื่อจริงหรือรูปจาก Google:** เก็บเฉพาะอีเมลกับรหัสบัญชี Google (`google_sub`) เข้าครั้งแรกผู้ใช้ตั้งชื่อเล่น ชั้นปี และเลือกน้องเป็ดเอง จึงยังคงความเป็นนิรนาม
- **Access Token:** อายุ 15 นาที
- **Refresh Token:** อายุ 30 วัน เก็บใน httpOnly cookie (JavaScript อ่านไม่ได้ ลดความเสี่ยง XSS) และหมุนใหม่ทุกครั้งที่ใช้ ถ้ามีการนำ token เก่ามาใช้ซ้ำ ระบบจะเพิกถอนทั้งชุด
- จำกัดความถี่การเรียก API (rate limit)
- **เหตุผลที่เปลี่ยนจาก OTP ทางอีเมล:**
  - อีเมล OTP ที่ส่งผ่าน Gmail มักเข้าโฟลเดอร์ Spam
  - Render แบบฟรีบล็อกการส่งอีเมลผ่าน SMTP ตั้งแต่ 26 ก.ย. 2025
  - ผู้ใช้ไม่ต้องจำรหัสผ่านเพิ่ม (Frictionless Entry)

## 3.5.5 ห้องสนทนา

- ห้องกลุ่ม (Mesh) จำกัดไว้ที่ 10 คนต่อห้อง (ปรับได้ด้วย `GROUP_ROOM_MAX`)
- เพิ่มปุ่ม “สุ่มคุย 1-1” และการเข้าห้องแบบปิดไมค์/ฟังอย่างเดียว
- ถามยืนยันก่อนออกจากห้องทุกกรณี (กดปุ่มออก เปลี่ยนไปหน้าอื่น กดย้อนกลับ ปิดแท็บ) พร้อมบอกว่าห้องจะปิดหรือสิทธิ์เจ้าของห้องจะย้ายไปให้ใคร กันการหลุดจากวงคุยเพราะกดพลาด
- รองรับ TURN server เพื่อให้ต่อเสียงผ่านเน็ตมือถือได้
- ปรับระดับเสียงหรือปิดเสียงเพื่อนแต่ละคนได้ มีผลเฉพาะเครื่องของผู้ฟัง (เพื่อนไม่รู้) และระบบจำค่าไว้ในเบราว์เซอร์
- หัวห้องมีปุ่มชวนเพื่อน: มือถือเปิดหน้าต่างแชร์ของเครื่อง (ส่งต่อทาง LINE ได้) คอมพิวเตอร์คัดลอกลิงก์ห้อง
- เน็ตหลุดระหว่างอยู่ในห้องจะขึ้นแถบ “การเชื่อมต่อหลุด กำลังเชื่อมต่อใหม่…” จนกว่าจะต่อได้
- ปุ่มไมค์มีคำบอกสถานะใต้ปุ่ม (ไมค์เปิด / ไมค์ปิดอยู่ / ขอใช้ไมค์)

## 3.5.6 คาราโอเกะ

- ซิงก์เพลงผ่าน Socket.IO: เพลงเล่นเองตั้งแต่ต้นจนจบ ไม่มีใครหยุด เลื่อน หรือคลิกที่วิดีโอได้ รวมถึง host (รายงานเดิมให้ host ควบคุมการเล่นและการหยุดชั่วคราว)
- host เป็นคนจับเวลาของห้อง ทุกเครื่องปรับตามเวลานี้จึงได้ยินตรงจังหวะกัน และ host ยังข้ามเพลงได้
- ถ้า host ออก ระบบย้ายสิทธิ์ให้คนที่อยู่ในห้องนานสุดอัตโนมัติ
- ค้นหาเพลงผ่าน YouTube Data API หรือวางลิงก์ YouTube
- การ์ดห้องคาราโอเกะในหน้ารายการห้องบอก “กำลังเล่น: ชื่อเพลง” หรือ “คิวว่าง” แบบเรียลไทม์ (ตรงกับ Low Cognitive Load ในบทที่ 2)
- ไม่มีเนื้อเพลงแบบเลื่อนอัตโนมัติแยกจากวิดีโอ ใช้วิดีโอคาราโอเกะจาก YouTube ที่มีเนื้อเพลงในตัวแทน (บทที่ 2 ข้อ UI Layout เขียนว่าฝั่งซ้ายมีเนื้อเพลงเลื่อนอัตโนมัติ)

## 3.5.7 ระบบดูแลความปลอดภัย

- ผู้ดูแลมีหน้า `/admin/reports` สำหรับ ซ่อนเนื้อหา / ปิดห้อง / ระงับบัญชี / ปลดระงับบัญชี / ยกเลิกรายงาน
- หน้าเดียวกันมีสถิติตามตัวชี้วัดข้อ 4.6
- หน้าข้อตกลงมีช่องทางขอความช่วยเหลือ: สายด่วนสุขภาพจิต 1323 และ 1669

## การออกแบบหน้าจอ (บทที่ 2 แนวคิด UX/UI)

- **เลือกโหมดสี:** ผู้ใช้เลือก ตามเครื่อง / สว่าง / มืด ได้เองในหน้า “ฉัน” (รูปเล่มพูดถึงความสบายตาตอนกลางคืน แต่ไม่ได้ระบุปุ่มเลือกโหมด) ระบบจำค่าไว้ในเบราว์เซอร์
- **Visual Contrast:** สีตัวอักษรทุกคู่ต่างจากพื้นหลังอย่างน้อย 4.5:1 ตาม WCAG 2.1 ระดับ AA
  - ตัวอักษรบนพื้นเหลือง/ส้มใช้เฉดที่เข้มขึ้น: เหลือง `#855a04` และส้ม `#a84b0b`
  - ข้อความ error และปุ่มลบใช้สีแดง `#c62828`
  - ถ้ารูปเล่มมีตารางสี (Color Palette) ให้เพิ่มเฉดเหล่านี้
- **Legibility:** ระยะบรรทัดของตัวอักษรไทยมากกว่าค่าเริ่มต้น (1.5–1.65) เพราะมีสระบน-ล่างและวรรณยุกต์ และตัวอักษรไทยเล็กสุด 12px
- **Duck Mascot:** น้องเป็ดเปลี่ยนท่าตามหน้า เป็ดใส่หูฟังในหน้าคาราโอเกะ และเป็ดแว่นในบอร์ด Q&A (รูปเล่มเขียนว่า “เป็ดถือแว่นขยาย” ระบบใช้อวาตาร์เป็ดแว่นไปก่อน จนกว่าทีมออกแบบจะทำภาพจริง)
- **สถานะการโหลด:** ระหว่างโหลดแสดงโครงหน้า (skeleton) แทนวงกลมหมุน หน้าที่โหลดไม่สำเร็จมีปุ่ม “ลองใหม่” และปุ่มส่งใจเปลี่ยนทันทีที่กดโดยไม่รอ server
- **มือถือ:** บอร์ดคำถามมีปุ่ม “ตั้งคำถาม” ลอยเหนือเมนูล่าง และปุ่มรายงานข้อความแชทมองเห็นบนจอสัมผัส

มีชุดทดสอบอัตโนมัติทั้งฝั่ง server (unit + integration กับฐานข้อมูลจริง) และฝั่ง client ดู [test-plan.md](test-plan.md)

## 3.5.9 และตารางที่ 4.4–4.5

- Vercel ส่งต่อ `/api` ไป Render (rewrite)
- Render ใช้ไฟล์ `render.yaml`
- Supabase เชื่อมต่อผ่าน Session pooler
- เข้าสู่ระบบด้วย Google Identity Services (ฟรี) ไม่ต้องใช้บริการส่งอีเมล
- TURN server สำหรับต่อเสียงผ่านเน็ตมือถือ ใช้ Metered แผนฟรี (500 MB ต่อเดือน)
- งบประมาณยังเป็น 0 บาท
- **เพิ่มในตาราง 4.4:** Prisma, Socket.IO, Tailwind CSS, pgAdmin, Google Cloud Console (OAuth Client ID)

## 5.3 ข้อจำกัดที่ควรเพิ่ม

- **เสียงร้องช้ากว่าเพลง:** เพลงเล่นจาก YouTube บนเครื่องของแต่ละคน ส่วนเสียงร้องส่งผ่านเครือข่าย จึงมาช้ากว่าเพลงเล็กน้อย (ประมาณ 0.2–0.3 วินาที)
- **จำนวนคนต่อห้อง:** ห้องแบบ Mesh รองรับคนต่อห้องได้จำกัด ถ้าต้องการห้องใหญ่ต้องใช้ media server (SFU)
- **ไม่ได้ยืนยันว่าเป็นนักศึกษา:** ค่าเริ่มต้นรับบัญชี Google ใดก็ได้ ถ้าตั้ง `ALLOWED_EMAIL_DOMAINS=mail.kmutt.ac.th` จะยืนยันได้ว่าเป็นนักศึกษา มจธ. แต่ยังไม่ได้ยืนยันว่าอยู่ในสาขาวิชา
- **ต้องมีบัญชี Google:** ผู้ใช้ต้องมีบัญชี Gmail หรือบัญชี Google ของมหาวิทยาลัยหรือองค์กร ถ้าใช้บัญชี `@mail.kmutt.ac.th` แล้วผู้ดูแลระบบของมหาวิทยาลัยปิดสิทธิ์ไม่ให้ใช้บัญชีกับแอปภายนอก ต้องขอให้สำนักคอมพิวเตอร์อนุญาตแอปนี้ก่อน
- **ข้อจำกัดของบริการฟรี:** Render หลับเมื่อไม่มีคนใช้ 15 นาที และ Supabase พักโปรเจกต์เมื่อไม่มีการใช้งาน 7 วัน
- **iPhone/iPad ปรับเสียงเพื่อนรายคนได้แค่ปิดเสียง:** Safari บน iOS ไม่ให้เว็บตั้งระดับเสียงของ `<audio>` จึงลดระดับทีละคนไม่ได้
